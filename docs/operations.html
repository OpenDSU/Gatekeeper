Overview

Operations

Host requirements

The host supplies the routing methods, rootFolder, createServerlessAPI, and registerServerlessProcess used by index.js. It also supplies the OpenDSU plugin environment and the $$ facilities referenced by handlers and plugins. Set AUTH_API_PREFIX before loading the module, because the module captures it at import time.

PERSISTENCE_FOLDER is set beneath the host's external-volume/balanceData. SERVERLESS_STORAGE defaults beneath external-volume/appStorage, and SERVERLESS_ID defaults to the package's Gatekeeper identifier. An absent SERVERLESS_AUTH_SECRET is generated for that process. Credential values must remain outside documentation.

Authentication routes

The registered handlers include sendCodeByEmail, loginWithEmailCode, loginWithPasskey, loginWithTotp, and logout. Passkey setup and account-management handlers also operate under the configured prefix. The route declarations in index.js and validation in handlers/auth.js define the accepted payloads.

Email-code delivery has development response behavior when NODE_ENV=development, LOGIN_MODE=direct, or the request origin equals http://localhost:8080. These branches are separate from normal email delivery and should be accounted for when integrating the host.

Middleware boundaries

The authentication-route middleware checks browser-like headers, with an IP_WHITELIST bypass. Header screening does not establish user identity. Session checks occur separately in the /proxy/* middleware. Its explicit readiness/public-method paths and trusted internal token path can bypass session lookup.

The IP-based user-creation limiter has an empty route-pattern list in securityMiddleware.js. The presence of its counters does not mean any route currently uses that limiter. UserLogin's per-email registration and login attempt checks are separate.

Dependencies and verification

package.json installation hooks clone persistence, authenticator, and plugin repositories, while the declared EmailPlugin dependency comes from Git. Installation therefore performs network and filesystem operations. No package-level test command is declared. tests/testSecurityMiddleware.js is a live-host probe with legacy route assumptions, and tests/smokeTest.js requires the plugin environment. Neither should be treated as a standalone, environment-free unit suite.
